# Retro PC Builder 5.0 (J2ME)

Ремонт и доработка существующего J2ME-проекта «Retro PC Builder» (сим 1979–2027:
сборка ПК, жизнь в комнате, барахолки, ремонт, эксперименты).
Это **не** новая игра с нуля: исходники восстановлены из архива
`RetroPcBuilder-4.8.jar` (он был загружен как `RetroPcBuilder-4.8 (2).png`),
декомпилированы и починены. Классов, написанных заново «с нуля», всего
несколько — они вынесены отдельно (см. таблицу ниже), всё остальное —
существующие классы игры (`Game`, `Db`, `LifeSim`, `City`, `WorkshopTools`,
`Exp`, `SoftSim`, `AudioEngine`, `Assets`, `Scene`, …).

```
RetroPcBuilder-5.0.jar   готовый MIDlet (90 записей, 2540 KiB)
RetroPcBuilder-5.0.jad   дескриптор для телефона/эмулятора
build.sh                 сборка без J2ME SDK (см. ниже)
src/rpc/**               исходники игры
src/rpc/j2me/**          тонкий слой MIDlet (Canvas, Gfx, Host, Keys)
harness/rpc/harness/**   десктопный прогон: рендер в BMP/PNG, звук в WAV, смоук-тест
stubs/**                 заглушки CLDC 1.1 / MIDP 2.0 (boot classpath)
docs/screens/**          кадры экранов, собранные харнессом
```

## Сборка

Нужен только JDK (javac 8) — J2ME SDK не требуется: API CLDC/MIDP
генерируется из `stubs/` в class-файлы и подставляется как `-bootclasspath`,
а игра компилируется с `-source 1.3 -target 1.3`, чтобы байткод остался
major 47 (его понимают старые телефоны).

```sh
./tools/setup_toolchain.sh     # один раз: скачивает javac + JRE в .toolchain/
./build.sh                     # jar + jad + проверка CLDC/MIDP
./build.sh --harness           # + десктопный харнесс и смоук-тест
./build.sh --harness --shots   # + кадры экранов в docs/screens/*.bmp (+ png)
```

`./build.sh --harness` прогоняет `rpc.harness.Smoke`: 8000 нажатий на всех
экранах (падений быть не должно), проверку навигации «кнопка → экран»,
проверку сохранения/загрузки и рендер звука в WAV.

## Что было сломано в 4.8 и как исправлено

### 1. Навигация была перепутана

`Game.input(int)` в 4.8 — это один метод на 850 строк из вложенных
`if (this.mode != N)`; обработчики экранов лежали внутри общей таблицы,
и действие `4` (`FIRE`), нажатое на разных экранах, попадало в чужие ветки.
Плюс на экране комнаты печатались подсказки «5: попить чай, 6: погладить,
7: лечь спать», но старый обработчик клавиш телефона вообще не доставлял
цифры в игру — они уходили в `KEY_NUM*` и терялись.

Что сделано:

* **Диспетчер по экрану.** `Game.input(action)` — короткий `switch (mode)`,
  у каждого нового экрана свой обработчик (`inputMenu`, `inputRoom`,
  `inputTea`, `inputSleep`), у остальных — `inputLegacy`. Ветка одного
  экрана физически не может изменить состояние другого.
* **Стек навигации.** `navPush`/`navBack`: любой переход записывается,
  `BACK` (`*`, `#`, soft-key) снимает верхнюю запись и возвращает ровно туда,
  откуда пришли. Раньше `BACK` из подэкрана кидал в корень меню, и счётчики
  `DOWN` в скрипте кадров уезжали на чужие строки.
* **Один источник правды для «горячих точек».** В комнате восемь объектов
  (`Room.HOT_*`): монитор, кружка, кот, лампа, кровать, дверь, стол, радио.
  Стрелки и цифры 1–8 ходят по одному и тому же списку, поэтому «1» — это
  всегда монитор, «2» — всегда кружка (чай), «5» — всегда кровать (сон).
* **Цифры как быстрый доступ.** В главном меню строки пронумерованы,
  цифра сразу открывает нужный экран; в городе 1–4 выбирают реплику,
  в мастерской 1–6 — инструмент, в лаборатории `←`/`→` листают по 10 опытов.

Итог: `Чай → экран чаепития`, `Сборка → сборка ПК`, `Город → город`,
`Каталог → каталог`; ни один экран не открывает чужой. Это закреплено
тестом в `Smoke.java`.

### 2. Графика была «оранжевыми квадратами»

Комната в 4.8 рисовалась одним прямоугольником с двумя линиями и парой
палочек — ни монитора, ни кровати, ни кота. Всё, что видит игрок, теперь
рисуется процедурно, без картинок (работает на любом экране и не занимает
места в jar):

| файл | что рисует |
|---|---|
| `src/rpc/Room.java` | комната: обои, окно с небом/погодой/городом/солнцем-луной, шторы, стол, CRT-монитор с «рабочим столом», корпус с вращающимся вентилятором, клавиатура, мышь, кружка с паром, лампа с конусом света, кот (спит/идёт), кровать, дверь, часы, постер, растение, пыль в луче |
| `src/rpc/Icons.java` | 16 пиксель-арт иконок 16×16 в виде символьных сеток: монитор, корпус, кружка, кровать, дверь, город, колба, плата, календарь, инфо, ключ, кот, радио, лампа, тележка, чип |
| `src/rpc/BuildView.java` | верстак сборки: материнская плата, сокет, кулер с лопастями, 4 планки ОЗУ, карты, корзины, БП, монитор, клавиатура, мышь, принтер — и спрайт каждой установленной детали |
| `src/rpc/Workshop.java` | приборы мастерской: сетка ножек CPU, гребёнка конденсаторов с вздутыми, шкала термопасты с зоной 40–60 %, радиатор в пыли, осциллограф с пульсациями, CMOS-батарейка |
| `src/rpc/Text.java` | метрики шрифта: индекс стиля (0/1/2) → масштаб, обрезка «…», фильтр символов, которых нет в шрифте |

Плюс анимации: пар над чашкой, лопасти кулера, снег/дождь/листва за окном,
молния, вращение вентилятора корпуса, «Z» над спящим котом, курсор-уголки
и номерные бейджи объектов, полоса прогресса ремонта.

### 3. Меньше текста, больше экрана

* Главное меню: было 8 строк-предложений, обрезанных посреди слова, — стало
  8 строк «иконка + одно слово + номер».
* Сборка: было 27 одинаковых текстовых строк — стало поле с рисунком ПК,
  карточка выбранного слота (деталь, цена, год, состояние) и 7 кнопок.
* Мастерская: вместо текстового дампа — список инструментов и живой прибор.
* Лаборатория: вместо двух строк фильтров — одна, освободившееся место
  отдано списку.
* «Об игре»: вместо 17 строк текста — 5 иконочных строк.

### 4. Прочие дефекты 4.8, которые пришлось починить

* `HostImpl.load()` читал ресурс из jar, а `save()` писал в RMS — прогресс
  никогда не возвращался. Теперь и то и другое через RMS.
* Стартовый экран блокировал первый `paint()`: загрузка каталога ушла
  в фоновый поток со сплэшем.
* `tone()`/`noise()` создавали по потоку на каждый звук — теперь через
  `AudioEngine` (клики, вентилятор, модем, BSOD).
* Шрифт: индексы стиля 0/1/2 использовались как пиксельный масштаб, из-за
  чего мелкий текст не рисовался; сведено в `Text.scale()`.
* Эмодзи из строк 4.8 (`\ufffd\ufffd\ufffd`) не имели глифов и рисовались
  пустыми квадратами — вычищены из исходников и отфильтрованы в `Text`.
* Заголовок экрана не обрезался и налезал на правую плашку — теперь
  обрезается по доступной ширине.
* Декомпилированные `readAll()` бросали непойманный `IOException` —
  закрыто, иначе класс не компилировался.

## Механики

Все блоки механик сохранены и изолированы по классам — экран только
показывает состояние и вызывает один метод:

| механика | класс | экран |
|---|---|---|
| сборка: сокеты, паста, статика, тесты | `Game` (slots/POST), `WorkshopTools` | «Сборка», «Мастерская» |
| ОС, BSOD, драйверы, вирусы, дефраг | `SoftSim`, `Assets`, `Game` (mode 13–28) | «ОС и сеть» |
| экономика: рынки, Avito, AliExpress, кредиты, инфляция | `City`, `Db`, `Game` (mode 9–12) | «Город», «Каталог» |
| ремонт: осциллограф, конденсаторы, паста, пыль | `WorkshopTools` + `Workshop` | «Мастерская» |
| лайф-сим: время, погода, сезоны, кот, радио, ТВ | `LifeSim` + `Room` | «Комната», «Чай», «Сон» |
| эксперименты: Win11 на железе 2005, Hackintosh и т.д. | `Exp` | «Лаборатория» |
| звук: HDD, модем, вентиляторы, мурчание | `AudioEngine` | везде |

## Кадры

`docs/screens/*.png` — реальные кадры, снятые харнессом с настоящего
`Game.paint()` (не макеты): меню, комната, чай, сон, сборка, магазин,
лаборатория, город, мастерская (3 инструмента), каталог, календарь, «об игре».

## Лицензия / происхождение

Исходники восстановлены из загруженного архива заказчика; правки — в рамках
этого репозитория.
