Настоящая iOS в QEMU

Что реально существует в 2026 году, на каком железе, и почему iOS 7–9 с iPhone 4s не запускается ни у кого. Оффлайн-справочник; источник — каталог ios-on-qemu/ в репозитории.

Главный ответ

iOS 8–9 на iPhone 4s не запустится нигде

Дело не в шифровании и не в лицензии. Чтобы загрузить iOS в QEMU, нужна модель машины — написанный человеком код, изображающий конкретный SoC: контроллер прерываний, PMU, NAND, дисплейный контроллер, тач, аудио, USB. iPhone 4s — это A5 (S5L8940x). Модели A5 не существует ни в одном публичном форке QEMU. iOS 8 и 9 жили ровно на A5/A6/A7 — то есть в той дыре, которую никто не закрыл. Документация QEMU формулирует это прямо: если машины нет в -machine help, образ «almost certainly not boot».

Четыре конфигурации, которые работают

полноценный GUI

iPhone 11 · iOS 14 · ChefKiss Inferno

Настоящий современный домашний экран iOS 14: Settings, Safari, Photos и остальные стоковые приложения. Мышь = палец. Интернет через VM-компаньон. Можно ставить собранные вами самими приложения (fake-sign через ldid) и пользоваться apt из root-shell.

Хост
x86_64 Linux
CPU
минимум 8 потоков; комфортно 8 ядер / 16 потоков (гость использует 7 эмулируемых ядер)
ОЗУ
16 ГБ минимум, 32 ГБ комфортно (4 ГБ гостю + 8 ГБ компаньону + десктоп)
Диск
~25 ГБ
Загрузка
~2.5 минуты (чистый TCG, софтверный рендер; GPU не используется)
Сложность
высокая — «вечер или два»
Прошивка
только iOS 14.0 beta 5 (18A5351d) для iPhone12,1, с серверов Apple

Официальный гайд просит не публиковать скрипты автоматизации установки, поэтому в репозитории для этого пути есть только проверка хоста. Инструкции: chefkiss.dev/applehax/inferno.

Чего нет: App Store, Apple ID/iCloud, Wi-Fi в настройках (интернет идёт по USB-линку), звонки, камеры, Face ID, свайп «назад» от края.

Грабли: собирать gcc, не clang; git submodule update --init; оставить -Ddebug=true — иначе restore падает с «SEP returned zero-length ART»; нужен настоящий SEP, на симулированном висит яблоко навсегда; при restore без окна — -display egl-headless, не none.

самый свежий настоящий iOS

iPhone X · iOS 16.7.16 (20H392) · lgrachov/ios-qemu

Немодифицированный userland iPhone X: launchd, системные демоны, backboardd, SpringBoard, экран блокировки с обоями, домашний экран с виджетами, стоковые приложения (Mail, Notes, Calendar, Clock, Maps…), Settings и Safari, который реально ходит в интернет. Экран 1125×2436 через ramfb, CoreAnimation рендерится на CPU. Звук, сеть (DHCP/DNS/TCP/QUIC/ HTTPS), часы следуют за хостом, тач мышью, аппаратная клавиатура. Экран блокировки примерно за минуту.

Хост
Mac на Apple Silicon — обязателен hvf
Софт
Homebrew qemu (проверено 11.0.2), GNU rsync, gh, ipsw, Xcode CLT
Диск
~40 ГБ
Ядро
собирается на GitHub Actions из открытого XNU (xnu-8796) + серия патчей

Это не Corellium. Corellium грузит собственное ядро Apple на виртуальном железе, похожем на iPhone; здесь ядро пересобирается из открытых исходников Apple, а generic-устройства QEMU маскируются под iPhone для userland. Из IPSW берутся только три диска (OS / SystemOS / AppOS) и device tree для MobileGestalt.

Чего нет: GPU, микрофон, камера, Bluetooth, сотовая связь, геолокация, Face ID. Безопасность выключена (разрешающий AMFI и Sandbox, заглушка AppleKeyStore, нет data protection) — ничего личного не хранить. Стандартные обои не подтягиваются, часть демонов перезапускается.

быстрый путь

iPod touch 1G · iPhoneOS 1.0 · qemu-ios

Оригинальный домашний экран 2007 года, тач мышью, встроенные приложения работают. Настройка меньше часа.

Хост
Linux (лучше Wayland) или macOS
Диск
~2 ГБ
Загрузка
~5 секунд
Сложность
низкая — меньше часа

Форк samhenrigold/qemu-ios эмулирует устройства достаточно полно, чтобы грузить стоковую прошивку от BootROM до домашнего экрана: тач, кнопки, дисплей, звук, Wi-Fi, USB (usbmux/AFC через libimobiledevice), постоянное хранилище, фейковая сотовая сеть, OpenGL ES через мост к хостовому GL. Платы: iPod-Touch-1G, iPhone-2G, iPod-Touch (2G), n18 (3G), n88 (3GS), iPod-Touch-4G, iPhone-4, ipad1.

Ограничения: интернета нет, изменения между запусками не сохраняются, из сна устройство не просыпается — Power только держать ~5 с, коротко жать нельзя.

Управление: мышь = палец, H = Home, =/- = громкость.

только консоль

iPhone 6s Plus · iOS 12.1 (16B92) · xnu-qemu-arm64

Загрузка настоящего ядра iOS 12.1 до интерактивного bash-4.4# под root. Проверено: Darwin Kernel Version 18.2.0 … RELEASE_ARM64_S8000 iPhone8,2, UID 0. SSH с хоста через tcp-туннель (root/alpine, порт 2222).

Хост
Linux (с патчами сокет-слоя) или macOS
ОЗУ
-m 6G, один эмулируемый CPU
Диск
~15 ГБ: hfs.main 6 ГБ + hfs.sec 2 ГБ
Сложность
средняя

Домашнего экрана не будет никогда. launchd поднимает SpringBoard (pid 35) и backboardd (pid 38), классы IOMobileFramebuffer и AGXFirmwareKextG5P существуют, но никто не открывает user client фреймбуфера: в модели машины нет ни дисплейного контроллера (CLCD/DCP), ни GPU (AGX/Metal), ни тача (multitouch/SPI), ни HID-клавиатуры. ramfb — только ранняя текстовая консоль XNU. Апстрим-issues #5/#12 открыты с 2019/2020 без движения, форк спящий.

Документированные ограничения форка: ramdisk только read-only и не больше 2 ГБ, связь исключительно по UART, «No devices emulation: screen, touch, wifi, BT or anything else».

На Linux нужны патчи: сокет-слой форка предполагает macOS (Darwin sockaddr layout, значение O_NONBLOCK, номера errno), а стоковый ramfb заявляет 16 bpp, но рисует 24 bpp → magenta-текст. iOS-сторона туннеля кросс-собирается без Apple SDK: clang -target arm64-apple-ios12.0 + рукописные минимальные Darwin-заголовки + ld64.lld + stub libSystem.tbd, подпись ldid.

Почему это не делается в виде APK

  • Приложениям Android недоступен /dev/kvm — вложенная виртуализация запрещена. Остаётся чистый TCG, на котором iOS 14 грузится 2.5 минуты даже на 8 ядрах Ryzen 7800X3D.
  • Гостю нужно 4–6 ГБ ОЗУ только на VM, путь A — ещё 8 ГБ на VM-компаньон. Ни один телефон не отдаст столько одному приложению.
  • Нет NDK, значит QEMU под Android не скросс-компилировать.
  • Единственный известный прецедент — QEMUAppleSilicon под Termux на Pixel 3, и он дал последовательную консоль, а не GUI.
  • Любой «iOS emulator APK» в интернете — вредонос или скам. Emulation General Wiki про одноимённое приложение iEmu пишет прямо: «Any Android app going by the name iEmu is a scam and should be avoided».

Проверить свой IPSW

В репозитории есть ipsw-inspect.py — только стандартная библиотека Python, без сети. Он читает BuildManifest.plist, раскладывает члены архива по корзинам (kernelcache / DeviceTree / ramdisk / rootfs / sep-firmware / trustcache / boot chain) и говорит, какому пути этот IPSW подходит. Для iPhone 4s он честно ответит «модели машины не существует».

python3 ipsw-inspect.py ~/iPhone_5.5_12.1_16B92_Restore.ipsw
python3 ipsw-inspect.py IPSW --need ios12-shell
python3 ipsw-inspect.py --paths
./check-host.sh              # потянет ли этот ПК какой-нибудь из путей

Юридическое

Прошивка iOS — собственность Apple; её лицензия запрещает запуск на не-Apple железе, обход шифрования подпадает под DMCA §1201. Все четыре проекта работают легально именно потому, что не распространяют файлы Apple: каждый требует скачать IPSW самому с серверов Apple. Правила upstream дополнительно: не делиться своими образами, ставить только собранные вами или открытые приложения — никаких App Store, взломанных или расшифрованных IPA.

Сгенерировано из каталога ios-on-qemu/. Все цифры — из документации самих проектов (alephsecurity, devos50/samhenrigold qemu-ios, ChefKiss Inferno, lgrachov/ios-qemu, eugenesflanagin-spec/ios-emu-linux), а не оценки на глаз. Ни один файл Apple здесь не хранится и не распространяется.
