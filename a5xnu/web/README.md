# web/ — порт эмулятора A5 на чистый JavaScript + APK

Python-реализация в `../` опирается на Unicorn (нативная библиотека). На Android
её нет: ни Unicorn, ни QEMU в WebView не загрузить. Поэтому ядро переписано
заново на JavaScript — **интерпретатор ARMv7 написан с нуля**, без готовых
эмуляторов, и упакован в настоящий подписанный APK.

Это не мок и не перерисовка интерфейса. Выполняются те же самые машинные слова,
что и в Python-версии, и состояние после загрузки совпадает **бит в бит**.

---

## Кросс-проверка двух реализаций

Один и тот же код ядра (`START_S`, 50 инструкций / 200 байт, собран keystone)
прогоняется и там, и там:

| | Python + Unicorn | JavaScript (этот порт) |
|---|---|---|
| тестов | 20/20 за 0.43 с | **78/78 за 0.20 с** |
| инструкций до handoff | 45094 | **45094** |
| `CPSR` | `0x600001F3` | **`0x600001F3`** |
| `pc` | `0x80017C40` | **`0x80017C40`** |
| `r0` (boot_args как VA) | `0x8FF01000` | **`0x8FF01000`** |
| `r5` (счётчик заполнения) | 512 | **512** |
| `L1[0x800]` / `L1[0x9FF]` / `L1[0xFFF]` | `0x4000040E` / `0x5FF0040E` / `0x40DA9001` | **то же** |
| `TTBR0` = `TTBR1` | `0x40DA0000` | **`0x40DA0000`** |
| `SCTLR` | `0x0000380D` | **`0x0000380D`** |
| перехватов cp15 | 3 mcr + 1 mrc | **3 mcr + 1 mrc** |
| негативный случай `memSize=0x80000000` | 2048 секций, `r5=0` | **2048 секций, `r5=0`** |
| скорость | 361 тыс. инстр/с | 339 тыс. инстр/с |

Запуск кросс-теста:

```sh
node tests-js/test_a5_boot.js      # 78 passed, 0 failed
```

Дизассемблер из `disasm.js` сверен с capstone на всех 50 инструкциях `ENTRY_CODE`
и на всей Thumb-программе — расхождений нет (capstone печатает `lsr r6, r1, #0xe`
там, где `disasm.js` печатает эквивалентную форму `mov r6, r1, lsr #14`).

## Состав

| файл | что это |
|---|---|
| `arm.js` | интерпретатор ARMv7 (ARM + Thumb) и страничная шина `Bus` |
| `a5.js` | модель платы k93ap: RAM, MMIO, AIC, Samsung UART, PMGR, теневой банк cp15 |
| `disasm.js` | дизассемблер ARM/Thumb для трассы |
| `entrycode.js` | **сгенерирован** `../tools/gen_entry_js.py` — 200 байт ядра загрузки |
| `testcode.js` | **сгенерирован** `../tools/gen_testcode_js.py` — 4 тестовые программы |
| `index.html`, `style.css`, `app.js` | интерфейс лаборатории |

Все файлы — обычные классические скрипты с общим пространством имён `A5`,
без ES-модулей и без сборки: WebView блокирует модули на `file://`.

`package.json` рядом (`{"type":"commonjs"}`) нужен только потому, что корень
репозитория объявляет `"type":"module"` и Node иначе отказывается выполнять
`require` в этих файлах.

### Генерация, а не ручное кодирование

Машинные слова нигде не набраны руками. `entrycode.js` и `testcode.js` собираются
keystone из того же ассемблерного текста, что и Python-версия, и оба генератора
поддерживают `--check`:

```sh
../tools/gen_entry_js.py   --check     # сверяет файл с текущим ассемблером
../tools/gen_testcode_js.py --check
```

Ручное кодирование слов в тестах уже один раз дало ошибку (`movw r1,#0` был
записан как `0xE30F1000`, то есть `#0xF000`) — поэтому его здесь нет вообще.

## Четыре настоящих бага, найденные только прогоном JS-тестов

Интерпретатор писался заново, и совпадение с Unicorn достигнуто не сразу.
Все четыре дефекта пойманы тестами, все исправлены:

1. **Маска `MOVT` была `0x0FF00000`** — она включает бит 22, поэтому `MOVT` не
   распознавался и проваливался в обработку данных, где исполнялся как **`CMP`**.
   Регистр сохранял младшую половину, и все обращения к MMIO шли не по тому
   адресу (симптом: журнал AIC пуст). Правильная маска — `0x0FB00000`.
2. **`step()` двигал PC только в ARM-ветке** — в Thumb PC не менялся вообще,
   защита от зависания сообщала `stalled`, а остальные регистры оставались нулями.
3. **Код операции Thumb «special data» брался из битов `[9:6]`** — на самом деле
   это биты `[9:8]`, а бит 7 — `D`, старший бит регистра-приёмника. Из-за этого
   `mov r4, r3` (`0x461C`) декодировался как «нереализовано».
4. **`PUSH`/`POP` в Thumb различались по битам `[10:8]`** — их разделяет **бит 11**
   (`push = 0xB400|list`, `pop = 0xBC00|list`, маска `0xFE00`), поэтому
   `pop {r4, pc}` (`0xBD10`) исполнялся как `PUSH`.

## Интерфейс

Приложение запускает загрузку сразу после открытия и показывает:

- регистры `r0…r15` с подсветкой изменившихся, флаги `N Z C V T I F` и режим;
- **17 проверок** результата загрузки, включая сверку с Unicorn;
- трассу исполнения (счётчик, адрес, машинное слово, мнемокод; `mcr/mrc` и
  переходы подсвечены);
- `boot_args` — все поля структуры, которую iBoot передаёт ядру в `r0`;
- таблицу страниц L1 в ключевых точках;
- теневой банк cp15 и журнал его перехватов;
- журнал обращений к нереализованному MMIO;
- консоль UART0;
- шестнадцатеричный просмотр памяти по произвольному адресу.

Локально:

```sh
cd web && python3 -m http.server 8765 --bind 0.0.0.0
# открыть http://localhost:8765/
```

## Сборка APK

APK собирается без Gradle, без Android Studio и без `dl.google.com` — конвейер в
`../../apk-toolchain/`. `MainActivity.class` выдаёт `tools/mkactivity.py`
(собственный писатель class-файлов, major version 49 — чтобы не нужен был
StackMapTable), `d8` превращает его в `classes.dex`, `aapt2` собирает ресурсы и
ассеты, `zipalign` выравнивает, `apksigner` подписывает v1+v2+v3.

```sh
export JAVA_HOME=/home/user/emuenv/lib/python3.11/site-packages/jdk4py/java-runtime
export PATH="$JAVA_HOME/bin:$PATH"
export ANDROID_SDK=/home/user/android-sdk

../../apk-toolchain/tools/build-apk.sh \
  --payload "$(pwd)" \
  --out ../../apk-toolchain/build/A5-Boot-Lab.apk \
  --version-name 1.0 --version-code 1
```

Результат: `A5-Boot-Lab.apk`, 60 КБ, `application-label:'A5 Boot Lab'`,
`minSdk 21`, `targetSdk 33`, подпись v1/v2/v3 = true. Установка:

```sh
adb install -r apk-toolchain/build/A5-Boot-Lab.apk
```

Каталог `build/` исключён из Git — APK воспроизводится одной командой.

Пути к `--payload` и `--out` нужно передавать **абсолютными**: скрипт делает
`cd` в корень `apk-toolchain/`, и относительный путь разрешится не от места
запуска.

## Что это за APK — честно

Это **настоящий эмулятор ARM**, выполняющий реальный протокол загрузки A5/XNU:
структура `boot_args` версии xnu-2107, построение таблицы страниц, тождественное
отображение ядра, включение MMU через cp15 и передача управления в Thumb-режим.
Всё это выполняется на телефоне и проверяется 17 утверждениями.

Это **не iOS**. Прошивки Apple в песочнице нет и быть не может: по кодовому
поиску GitHub не находится ни одного `kernelcache`, ни одного `DeviceTree`, ни
одного `ipsw` для iOS — только macOS-образы и LFS-указатели. Единственная
известная модель A5 (`hw/arm/k93ap.c` в `b1ackmarket/qemu-n90ap`) доведена до
фазы конструкторов kext, без консоли, графики и оболочки; открытых загрузок
iOS 6 с графикой не существует. Приложение «эмулятор iOS» в маркете — это
мошенничество или вредоносное ПО.

Здесь сделано то, что сделать можно: собственное ядро эмулятора, собственная
модель платы и собственная реализация протокола загрузки, сверенная с Unicorn.
